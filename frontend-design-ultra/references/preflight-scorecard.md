# Preflight Scorecard

Run before saying a substantial UI is done.

## Binary Shipping Checks

Mark each applicable item `Pass`, `Fail`, `Needs Review`, or `Not Applicable`; never average a failure into a creative score.

- The requested routes, states, content, and output-integrity contract are complete.
- The design contract records page job, audience intent, conversion/trust spine, asset reality, strategy lane, signature move, token contract, mobile recomposition, and verification plan; missing research or inputs are explicitly labeled.
- First viewport makes the page job, proof/action path, and primary action understandable without clipped key content.
- Compact laptop, standard desktop, wide monitor, mobile, and reduced-motion/no-pin layouts have no overflow, overlap, occlusion, or unusable controls.
- Navigation intentionally fits or collapses; headings, landmarks, labels, errors, focus order/visibility, contrast, and keyboard paths meet the agreed accessibility target. Placeholder text is never the only label.
- Loading, empty, error, disabled, hover, focus, and active states exist where applicable.
- Reduced-motion users receive complete, visible final states; essential information never depends on animation, and no-pin layouts remain compact and filled.
- Media dimensions and font strategy protect layout stability; the agreed lab or field performance budget is met or explicitly unresolved.
- Runtime, console, network, hydration, build, lint, test, and typecheck evidence is clean where applicable.
- Metadata, social image, 404/back path, footer, consent, and legal requirements exist where applicable.
- Public output contains no private paths, confidential identifiers, copied-source claims, placeholders, fake proof, or unverifiable awards/metrics/logos.
- Major claims name their evidence and confidence. Browser-dependent claims without authorized evidence say `Needs Browser Verification`.

For performance, keep evidence classes explicit: field/RUM data names source, population, date range, and device segment; lab data names tool/version, route, profile, date, and run count. Lab results do not prove field INP.

## Creative Jury

Use this Awwwards-oriented weighting for critique, not certification:

- Design, 40%: first impression, composition, typography, palette, assets, responsive craft, intentional wide-screen use, and coherence.
- Usability, 30%: clarity, navigation, readability, interaction, mobile task flow, and conversion path.
- Creativity, 20%: subject-specific concept, memorable but justified signature move, adjacent-route variety within stable brand DNA, and avoidance of default visual clusters.
- Content, 10%: message, proof, voice, media, trust, and next action.

Score each dimension 1-5, show the weighted result, and give evidence-backed rationale. Any dimension below 4 is a creative fix target. Accessibility, correctness, runtime, and performance are decided by the binary shipping checks, not by jury arithmetic.

## AI Tell Sweep

Reject by default:

- centered dark mesh hero
- AI-purple/blue glow
- three equal feature cards
- glass card over hero image
- random pills and badges
- plain text fake logo walls
- fake-perfect numbers
- generic avatars and names
- div-based fake screenshots
- decorative SVG illustrations as hero proof
- split header with left headline and right filler paragraph
- bento grid with identical white cards
- long divider-heavy spec tables
- arbitrary z-index inflation

## Done Definition

Done means the design contract is implemented, all applicable binary shipping checks pass, and remaining Creative Jury repair targets are honestly reported. For browser-verifiable work, use build -> inspect/capture when authorized -> compare -> patch -> recheck. A build alone is not visual proof; unavailable authorized evidence returns `Needs Review`, not a polite pass.

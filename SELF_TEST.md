# Self Test

Run before publishing a release.

## Validation

- [ ] `npm run lint`, `npm test`, and `npm run build` pass.
- [ ] `frontend-design-ultra` validates with the Codex skill validator.
- [ ] Public files contain no private source, construction, or external-repo dependency notes.
- [ ] All slash parameters route to either `SKILL.md` logic or a reference.
- [ ] Major workflows have output contracts.
- [ ] Hard gates cover accessibility, correctness, performance, mobile, reduced motion, and evidence.
- [ ] Evals have prompt and expected structure pairs.
- [ ] Examples are public, generic, and do not contain private data.
- [ ] Raw third-party research evidence is outside the repository and known cloud-sync roots, not merely gitignored.
- [ ] `RIGHTS.md`, both third-party notice files, and the installable `LICENSE` are present and current.
- [ ] Every public image/video is enumerated in `docs/assets/media-provenance.json` with an exact hash and claim boundary.

## Reference And Motion Evidence

- [ ] Every live-site scan records an explicit rights basis, review date, reviewer identifier, effective URL, contract version, and private publication policy.
- [ ] Complete, partial, unsupported, failed, and timed-out scans remain distinct.
- [ ] The newest relevant v2 attempt is published only as sanitized diagnostic metadata; partial, failed, unsupported, and strict-ineligible complete outcomes cannot become normal observations or motion-verification evidence.
- [ ] Entrance frames use fresh isolated contexts and report target-versus-actual timing rather than silently relabelling missed frames.
- [ ] Desktop, real touch/mobile, reduced-motion, verified scroll, continuous-video, runtime, network-policy, and artifact-budget states are present where the contract claims them.
- [ ] Machine observations remain complete-only and human-review-pending, and contain no private paths, raw captures, request headers, or source code.
- [ ] Every observation digest binds the manifest, derived record, contact sheet, and all referenced screenshot, video, trace, and reduced-motion artifact contents while preserving traversal, symlink, count, and size limits.
- [ ] Corpus lifecycle counts match records; machine capture alone does not promote a candidate to `scanned`.
- [ ] Motion source digests match the selected public observation and no recipe is `verified` without build evidence.
- [ ] Motion lifecycle counts use `recipe`, never `prototype`; recipes describe complete implementation contracts without claiming code, a build, or verification.
- [ ] Idea, candidate, and recipe entries contain no `verificationEvidence`; verified and promoted entries include a safe repository-relative implementation path, exact commit, digest, tested viewports, completed checks, date, and review type.
- [ ] Award-platform links are labelled discovery references and never treated as capture or redistribution permission.

## Showcase Evidence

- [ ] Showcase lint, typecheck, contrast validation, production build, and static-export validation pass on the declared runtime.
- [ ] The six routes pass desktop, touch/mobile, reduced-motion, no-JavaScript, scroll, runtime, target-size, focus, and local-interaction checks.
- [ ] The public six-route gallery and entrance storyboard are regenerated only after a zero-issue audit.
- [ ] The public capture manifest binds the exact export and private audit digests.
- [ ] `scripts/validate-repo.mjs` detects a stale export, stale audit, changed media hash, missing route render, or undeclared public asset.
- [ ] Fixture labels, facts, SVG/CSS visuals, and media are repository-authored declarations; this is not a trademark-clearance or benchmark claim.

## Benchmark And Claims

- [ ] Benchmark protocol, result, matrix, environment, run, capture, packet, and jury schemas validate.
- [ ] Holdout commitments bind benchmark version and frozen protocol digest.
- [ ] Condition mappings and keys remain private until the vote freeze.
- [ ] Jury records are described as pseudonymous, with consent, retention, redaction, invalid-vote, and exclusion rules.
- [ ] A completed/public result requires execution pins, capture evidence, jury coverage, rights review, limitations, and a publication decision.
- [ ] Pending status contains zero completed runs, zero valid votes, no outcome statistics, and no superiority claim.
- [ ] Curated showcases, expected outputs, prompt contracts, stars, and code volume are never presented as comparative visual results.

## Release And Supply Chain

- [ ] Git tracked-file inspection fails closed in a real worktree.
- [ ] GitHub Actions and containers use immutable full-SHA references.
- [ ] Root and showcase lockfiles report no unresolved high/critical advisories.
- [ ] Dependabot covers root, showcase, and GitHub Actions.
- [ ] PowerShell and Bash installers preserve staging, validation, dry-run, backup, rollback, literal-path, and local-working-tree guarantees.
- [ ] The installable archive contains README, SKILL, LICENSE, third-party notices, routed references, scripts, and schemas only.
- [ ] The deterministic packager verifies checksums, safely extracts to a temporary directory, and compares every extracted byte with its manifest.
- [ ] A committed source claim matches a clean full Git HEAD; dirty or unverifiable builds use `uncommitted` or `unknown`.
- [ ] Release artifacts contain no third-party captures, benchmark secrets, juror mappings, unredacted free text, credentials, customer data, or absolute local paths.

## Responsive Viewport System Checks

## Ultimate Design Operating System Checks

- [ ] `/research` forces a research packet, source mechanics, evidence gaps, and confidence tiers before premium decisions.
- [ ] New substantial websites and large redesigns are design-system-first: generated or adopted typography, color, surface, grid, spacing, component, motion, asset, accessibility, and performance system.
- [ ] No default typography/color gate blocks Inter/Roboto/Arial/system UI and generic blue/purple glow unless explicitly justified.
- [ ] `/analyse` and `/polish` use diagnosis lenses, root cause, Keep/Delete/Replace/Rebuild, severity, and evidence confidence.
- [ ] Website-type playbooks route agency/studio, SaaS/app, dashboard, ecommerce, hospitality, portfolio/showroom, local, legal/finance/healthcare, luxury/editorial, and startup/product launch.
- [ ] Editorial motion uses intent, one-owner-per-element, GSAP/Framer/CSS decision, choreography layers, motion budget, mobile alternative, and reduced-motion fallback.
- [ ] Implementation recipes cover responsive hero, editorial split, full-bleed media, sticky chapter, cursor-follow preview, product object stage, dashboard density, pricing/proof board, immersive footer, and mobile recomposition.
- [ ] Evals include design-from-zero-system-first, analyse-polish-professional-lens, and editorial-motion-system.

## Full Mechanism Parity Checks

- [ ] Visual work produces a taste profile object before decisions: mode, domain, lane, preset, variance, motion, density, evidence depth, asset mode, hard constraints.
- [ ] Style work uses one primary archetype and at most one support archetype.
- [ ] Brandkit work includes Brand DNA, symbol concept path, board grammar, application proof, and token handoff.
- [ ] Imagegen work outputs one readable visual per major section or screen unless grouping stays inspectable.
- [ ] Image-to-code work extracts first and implements second; unclear details trigger regeneration or explicit uncertainty, not guessing.
- [ ] Redesign work preserves functional strengths and mutates the smallest set of systems that fixes root causes.
- [ ] Final outputs contain no placeholders, no hidden TODOs, no fake proof, no omitted states, and no unverifiable public claims.
- [ ] `/project-fit` distinguishes installed/configured facts from starter prose and does not call a documentation-only context pack runnable.
- [ ] A project-fit machine contract resolves a shipped capability profile; unknown profiles, missing mapped artifacts, omitted profile-required scripts, failed machine capabilities, and rejected defaults block `bridge-ready`/`profile-ready`.
- [ ] Browser or screenshot parameters never override user, host, or project capture policy.
